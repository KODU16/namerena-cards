# 大逃杀：平台维护 Agent 接入说明

此说明用于让 `namerena-platform` 的维护 Agent 安全地启用 cards 大逃杀。cards 只交付已构建的浏览器资源与版本化对局包；权威身份校验、房间状态、结算与定时推进必须继续由平台代码负责。

## 变更边界

- cards 的玩法、地图、物品或前端改动直接合入 cards `main`；发布包必须来自 `npm run build:site`，不得手工拼接单个文件。
- 平台接口、持久化、认证、限流和功能开关只在 `namerena-platform` 的私有分支或 PR 中修改并审查。
- 不要让 cards 的静态页面承担权威裁决，也不要将密钥、连接信息或运行环境拓扑写入 cards。

## 启用前门槛

1. 在 cards 的目标提交运行 `npm run build:site`、`python server/arena_smoke_test.py` 与 `python server/arena_world_test.py`；三者均须成功。
2. 在平台 PR 运行其多人接口测试，确认匿名请求、CSRF、重复操作、私房密钥、超时自动出牌、缩圈结算和断线恢复仍受平台校验。
3. 确认发布包的清单与文件完整，并且平台只接受与当前协议兼容的包；校验失败应拒绝加载，而不是降级执行未知规则。
4. 仅在以上检查通过后，由平台维护者启用多人功能开关。若任一步失败，保持关闭并返回明确的“多人模式等待主站启用”提示。

## 上线验收

- 已登录用户能创建/加入私房，公房可正常开始、推进、缩圈与结算。
- 对局操作只由平台验证；10 秒出牌超时会在服务端自动选择一张可用手牌。
- 同名 AI 的延迟移除、AI 战斗及尸体搜刮、奖励和结算均由权威状态重载后保持一致。
- 发布新 cards 包时，正在进行的对局要么能以同一规则继续，要么被平台明确拒绝并安全回退；不能混用不同版本的规则。
- 未通过验收或出现异常时，关闭多人功能即可停止新对局入口；保留既有数据以便调查，禁止以删除对局数据作为恢复方式。

## 维护责任

cards 维护者负责可构建的静态包与本地玩法回归；平台维护者负责私有平台改动、生产审查、启用与回退。此文不包含服务器结构、路径、端口、凭据或部署命令。
